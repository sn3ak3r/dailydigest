# Reverse-a-function drill — 2026-11-19

Target: Windows x86-64 (args in `ecx`, `edx`; return in `eax`).

Reverse this short function to equivalent C:

```asm
mystery:
    add     ecx, edx
    mov     eax, -1
    cmovnc  eax, ecx
    ret
```

What does it return for (10, 20) and for (0xFFFFFFF0, 0x20)?

---

## Answer

```c
unsigned mystery(unsigned a, unsigned b) {
    unsigned sum = a + b;
    return (sum < a) ? 0xFFFFFFFFu : sum;   // saturating unsigned add
}
```

Results: 30, and 0xFFFFFFFF (the true sum 0x1_0000_0010 doesn't fit in 32 bits).

## Explanation

- `add` sets the carry flag (CF) when the *unsigned* result wraps past 2^32; that's the overflow signal here, not OF (which is for signed).
- `mov eax, -1` loads the "max" fallback. `mov` never changes flags, so CF from the `add` survives to the next instruction.
- `cmovnc` ("move if no carry") overwrites eax with the sum only when nothing wrapped; otherwise eax stays 0xFFFFFFFF. Result: the sum clamps at UINT_MAX instead of wrapping, with no branch.
