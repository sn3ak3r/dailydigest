# Reverse-a-function drill — 2026-10-04

Target: Windows x86-64 (arg in `ecx`, return in `eax`).

Reverse this short function to equivalent C:

```asm
mystery:
    mov     eax, ecx
    cdq
    and     edx, 7
    add     eax, edx
    sar     eax, 3
    ret
```

What does `mystery(int x)` compute? Why not just `sar eax, 3`?

---

## Answer

```c
int mystery(int x) {
    return x / 8;
}
```

Signed division by 8, rounding toward zero.

## Explanation

- `cdq` sign-extends `eax` into `edx`: `edx` is all 1s if `x < 0`, else 0. `and edx, 7` turns that into a bias of 7 (negative) or 0.
- `sar` alone rounds toward negative infinity (`-1 >> 3` = -1), but C's `/` truncates toward zero (`-1 / 8` = 0). Adding 7 first to negatives fixes this.
- Unsigned division would be a plain `shr`; the bias exists only because of signedness.
