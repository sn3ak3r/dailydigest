# Reverse-a-function drill — 2026-11-25

Target: Windows x86-64 (arg in `ecx`; return in `eax`).

Reverse this short function to equivalent C. One `test`, two different answers pulled out of the same flags:

```asm
mystery:
    xor     eax, eax
    xor     edx, edx
    test    ecx, ecx
    setg    al               ; al = 1 if ecx > 0 (signed)
    setl    dl               ; dl = 1 if ecx < 0 (signed)
    sub     eax, edx
    ret
```

What does it return for 42, 0 and -7?

---

## Answer

```c
int mystery(int x) {
    return (x > 0) - (x < 0);
}
```

Results: 1, 0 and -1. It's the "sign" function, the same pattern as a branchless qsort comparator `(a > b) - (a < b)`.

## Explanation

- `test ecx, ecx` ANDs ecx with itself just to set flags, so it acts like `cmp ecx, 0`. Both `setg` and `setl` read those flags, and neither changes them, so one test answers two questions.
- `setcc` writes only one byte, so eax and edx are zeroed **before** the `test`. Doing it after would wipe the flags, since `xor` sets them.
- g/l are the signed conditions (a/b are the unsigned ones). Subtracting the two 0/1 results gives 1, 0 or -1 without a single jump.
