# Reverse-a-function drill — 2026-10-25

Target: Windows x86-64 (args in `rcx`, `edx`, `r8d`).

Reverse this short function to equivalent C:

```asm
mystery:
    push    rdi
    mov     rdi, rcx
    mov     eax, edx
    mov     ecx, r8d
    rep stosd
    pop     rdi
    ret
```

What does it do, and why does it save `rdi` and shuffle `rcx` around?

---

## Answer

```c
void mystery(int *p, int v, int n) {
    for (int i = 0; i < n; i++)
        p[i] = v;
}
```

An inlined `memset`-style fill of `n` dwords with `v`.

## Explanation

- `rep stosd` hard-wires its operands: store `eax` to `[rdi]`, add 4 to `rdi`, decrement `rcx`, repeat while `rcx != 0`. So the pointer must go to `rdi`, the value to `eax`, the count to `ecx` (the `mov rdi, rcx` must come before `rcx` is overwritten).
- On Windows x64 `rdi` is callee-saved (non-volatile), so the function pushes/pops it; `rax`, `rcx`, `rdx` are volatile and free to clobber.
- If `n` is 0, the `rep` does nothing; the direction flag is assumed clear (Windows ABI guarantees this on entry).
