# Drill: Reverse to C — 2026-09-01

Target: Windows x86-64 (MSVC calling convention: `rcx`, `edx` = arg1, arg2).

Reverse this disassembly to equivalent C:

```asm
func:
    xor     eax, eax        ; eax = 0
    test    edx, edx
    jle     done
loop_top:
    cmp     dword ptr [rcx], 0
    je      skip
    inc     eax
skip:
    add     rcx, 4
    dec     edx
    jnz     loop_top
done:
    ret
```

What does `func(int* arr, int n)` compute, and what does it return?

---

## Answer

```c
int func(int* arr, int n) {
    int count = 0;
    for (int i = 0; i < n; i++) {
        if (arr[i] != 0) count++;
    }
    return count;
}
```

- `rcx` is walked as a raw pointer (`add rcx, 4` advances by one `int`, 4 bytes) rather than indexed with a scaled base+offset — each iteration dereferences `[rcx]` directly instead of `[base + idx*4]`.
- `dec edx` / `jnz loop_top` counts `n` down to zero instead of comparing an incrementing index, so the loop runs exactly `n` times with no explicit index variable.
- `cmp`/`je skip` skips the `inc eax` for zero elements, so `eax` ends up holding the count of nonzero elements — the function's return value per the Windows x64 convention.
