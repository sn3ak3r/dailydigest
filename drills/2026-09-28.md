# Reverse-a-function drill — 2026-09-28

Target: Windows x86-64 (MSVC calling convention: first pointer arg in `rcx`, second in `rdx`, return in `eax`).

Reverse this short function to equivalent C:

```asm
mystery:
    xor     eax, eax
loop_top:
    movzx   r8d, byte ptr [rcx]
    movzx   r9d, byte ptr [rdx]
    cmp     r8d, r9d
    jne     diff
    test    r8d, r8d
    je      done
    inc     rcx
    inc     rdx
    jmp     loop_top
diff:
    mov     eax, r8d
    sub     eax, r9d
    ret
done:
    ret
```

What does `mystery(const char *a, const char *b)` compute?

---

## Answer

```c
int mystery(const char *a, const char *b) {
    while (*a == *b) {
        if (*a == 0)
            return 0;
        a++;
        b++;
    }
    return (unsigned char)*a - (unsigned char)*b;
}
```

It's a hand-rolled **`strcmp`**: byte-by-byte comparison that stops at the first mismatch or shared null terminator.

## Explanation

- `movzx r8d/r9d, byte ptr [...]` zero-extends each byte read so the later `sub` produces the classic unsigned-byte-difference result `strcmp` returns.
- `jne diff` breaks out on the first mismatching byte; `test r8d,r8d` / `je done` catches equal bytes that are both the string's null terminator, returning 0 (`eax` was zeroed up front).
- The `inc rcx` / `inc rdx` pair advances both pointers in lockstep, mirroring the C loop's `a++; b++;`.
