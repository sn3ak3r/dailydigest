# Reverse-a-function drill — 2026-11-28

Target: Windows x86-64 (unsigned arg in `ecx`; return in `eax`).

Reverse this function to equivalent C. Two new things here: `shr` drops a bit into the carry flag, and `adc` ("add with carry") adds that flag back in.

```asm
mystery:
    mov     eax, ecx
    shr     eax, 1           ; CF = the bit shifted out (old bit 0)
    adc     eax, 0           ; eax = eax + 0 + CF
    ret
```

What does it return for 7, 8 and 0xFFFFFFFF?

---

## Answer

```c
unsigned mystery(unsigned x) {
    return (x >> 1) + (x & 1);   // x / 2, rounding halves up
}
```

Results: 4, 4 and 0x80000000.

## Explanation

- The last bit a shift pushes out lands in CF. For `shr eax, 1` that's the old bit 0, so CF = 1 exactly when x is odd.
- `adc eax, 0` adds nothing except the carry, so odd inputs get +1: 7 → 3 + 1 = 4, 8 → 4 + 0 = 4.
- It's the same as `(x + 1) / 2` but can't overflow. For 0xFFFFFFFF, `x + 1` wraps to 0, while this gives 0x7FFFFFFF + 1 = 0x80000000.
