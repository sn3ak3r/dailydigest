# Daily Drill — 2026-08-27

**Format:** decode one instruction
**Target:** Windows x86-64

Decode this byte sequence into its full assembly instruction (mnemonic + operands):

```
48 8D 05 12 34 00 00
```

Break down each piece: the REX prefix, the opcode, and the ModRM byte (mod, reg, rm fields). Pay special attention to what `rm=101` means when `mod=00` — it isn't a normal register or [reg] memory form.

---

## Answer

```
lea rax, [rip + 0x3412]
```

**Explanation:**
1. `48` is REX.W (W=1), so operands are 64-bit. `8D` is the `LEA` opcode (load effective address, no memory access, just computes it).
2. `05` is the ModRM byte: `mod=00`, `reg=000` (destination = `rax`), `rm=101`.
3. Normally `mod=00, rm=101` would mean `[rip-relative form is the exception]` — on x86-64, this specific combination is reserved for **RIP-relative addressing**, not `[disp32]` absolute (that's a 32-bit-mode-only encoding). The following 4 bytes (`12 34 00 00`, little-endian) are a signed `disp32` added to the address of the *next* instruction, giving `[rip + 0x3412]`.
