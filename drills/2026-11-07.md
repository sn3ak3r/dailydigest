# Reverse-a-function drill — 2026-11-07

Target: Windows x86-64 (args in `ecx`, `edx`).

Reverse this short function to equivalent C:

```asm
mystery:
    mov     eax, ecx
    mul     edx
    mov     eax, edx
    ret
```

What does it return for (3, 5), (0x10000, 0x10000), (0xFFFFFFFF, 2) and (0x80000000, 0x80000000)?

---

## Answer

```c
unsigned mystery(unsigned a, unsigned b) {
    return (unsigned)(((unsigned long long)a * b) >> 32);   // high half of 64-bit product
}
```

Results: 0, 1, 1, 0x40000000.

## Explanation

- One-operand `mul r/m32` (F7 /4) multiplies eax by the operand as unsigned and writes the 64-bit product to edx:eax (high:low); eax is an implicit input.
- Here the operand is edx itself, read before the result overwrites it, so `mov eax, edx` then returns the high 32 bits, discarding the low half.
- It sets CF/OF when edx is nonzero (product didn't fit in 32 bits); `imul` has a signed one-operand form.
