# Mini Crackme — 2026-08-23

Target: Windows x86-64. `check` takes a pointer to a null-terminated
ASCII string in `rcx` (Windows x64 calling convention) and returns
`al = 1` if the string is the password, else `0`.

```asm
check:
    mov     r8, rcx            ; r8 = input pointer
    xor     eax, eax           ; eax = rolling checksum
    xor     edx, edx           ; edx = index
.loop:
    movzx   ecx, byte ptr [r8+rdx]
    test    ecx, ecx
    je      .done
    rol     eax, 1
    add     eax, ecx
    inc     edx
    jmp     .loop
.done:
    cmp     eax, 0x20F
    sete    al
    ret
```

Find an ASCII password that makes `check` return 1.

---

**Answer:** `KEY`

**Explanation:**
- Each iteration does `acc = rol(acc, 1) + byte`, i.e. rotate the
  running checksum left by one bit, then add the next character's
  ASCII value — a classic rolling-hash accumulator.
- Since the accumulator stays small here, bit 31 is always 0, so
  `rol eax, 1` behaves just like `acc * 2`. For `"KEY"`:
  `acc = ((0*2+'K')*2+'E')*2+'Y' = ((75)*2+69)*2+89 = 527 = 0x20F`.
- `0x20F` matches the target constant, so `cmp`/`sete` sets `al = 1`
  and the check passes for `"KEY"`.
