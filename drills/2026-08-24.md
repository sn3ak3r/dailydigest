# Drill 2026-08-24 — Decode One Instruction

Target: Windows x86-64.

Decode this instruction, byte by byte, and state what it does:

```
48 63 41 08
```

Give: the mnemonic and full operand form, what each byte/field encodes
(prefix, opcode, ModRM), and the resulting semantics in plain English.

---

## Answer

**`movsxd rax, dword ptr [rcx+8]`**

- `48` — REX.W prefix: operand size is 64-bit (required for `movsxd`'s
  destination).
- `63` — opcode for `MOVSXD` (move with sign-extension, 32→64 bit).
- `41` — ModRM byte `01 000 001`: mod=01 (register + disp8 addressing),
  reg=000 (destination = `rax`), rm=001 (base register = `rcx`).
- `08` — the disp8 operand: `+8`.

It reads the 32-bit dword at `[rcx+8]`, sign-extends it to 64 bits, and
stores it in `rax`. This is the classic pattern for loading a signed
`int` field (e.g. an array index or count) out of a struct pointed to
by `rcx` — the standard first-argument register in the Windows x64
calling convention — while widening it to a 64-bit value suitable for
pointer arithmetic.
