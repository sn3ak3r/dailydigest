# Decode One Instruction (Windows x86-64)

Decode this 3-byte sequence into a full x86-64 instruction (name it, and state every operand):

```
48 85 D8
```

---

## Answer

`test rax, rbx`

- `48` is `REX.W` (W=1, R=0, X=0, B=0) — no register-field extension bits, just 64-bit operand size.
- `85` is the opcode for `TEST r/m64, r64`. `TEST` computes a bitwise `AND` of its two operands purely to set flags (`ZF`, `SF`, `PF`) — the result itself is discarded, nothing is written back.
- The `ModRM` byte `D8` = `11 011 000`: `mod=11` selects register-direct addressing for both operands, `reg=011` is register index 3 (`rbx`), `rm=000` is register index 0 (`rax`). For this opcode `reg` supplies the second operand and `rm` the first, giving `test rax, rbx`.
- In practice `test rax, rbx` is almost always followed by a conditional jump like `jz`/`jnz` — it's the idiomatic way to check "are these two registers bitwise-disjoint / does their AND come out zero" without needing a spare register to hold the result.
