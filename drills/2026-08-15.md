# Decode One Instruction: x86-64 (Windows)

New tool for today: `lea dst, [expr]` ("load effective address") computes
the address `expr` would resolve to and stores that *address* in `dst` —
it never reads memory. `[base + index*scale]` is a common addressing
form; compilers use `lea` as a fast way to do `base + index*scale` math
without a real memory access.

Here is one raw x86-64 instruction as bytes, captured from a disassembler
on a 64-bit Windows binary:

```
48 8D 04 D9
```

Decode it into assembly. What instruction is this, and what does it
compute?

(Hint: `48` is a REX.W prefix meaning 64-bit operands; `8D` is the `lea`
opcode; the byte after the opcode is a ModRM byte, and when its low 3
bits are `100` a SIB byte follows to encode `base + index*scale`.)

---

**Answer: `lea rax, [rcx + rbx*8]`**

1. `48` = REX.W (64-bit operands). `8D` = `lea` opcode, reg field selects
   the destination register.
2. ModRM `04` = `00_000_100` — mod=00 (no displacement), reg=000
   (`rax`, the destination), rm=100 (means "read a SIB byte next").
3. SIB `D9` = `11_011_001` — scale=11 (×8), index=011 (`rbx`), base=001
   (`rcx`), giving `rax = rcx + rbx*8` — pure address arithmetic, no
   memory read.
