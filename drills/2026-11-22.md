# Reverse-a-function drill — 2026-11-22

Target: Windows x86-64 (arg in `ecx`; return in `eax`).

Reverse this short function to equivalent C. There's no `div` anywhere, yet it divides:

```asm
mystery:
    mov     eax, ecx
    mov     edx, 0AAAAAAABh
    mul     edx              ; edx:eax = eax * edx (unsigned)
    shr     edx, 1
    mov     eax, edx
    ret
```

What does it return for 10 and for 100?

---

## Answer

```c
unsigned mystery(unsigned x) {
    return x / 3;
}
```

Results: 3 and 33.

## Explanation

- `div` is slow, so compilers replace division by a constant with a multiply by a "magic number": 0xAAAAAAAB ≈ 2^33 / 3 (rounded up).
- One-operand `mul` puts the 64-bit product in edx:eax. Taking only edx is already `>> 32`; `shr edx, 1` adds one more, so the total is `(x * 0xAAAAAAAB) >> 33`, which is x × (2^33/3) / 2^33 = x/3.
- The magic is rounded up just enough that the result matches the true floor of x/3 for every 32-bit unsigned x. When you see `mul` by a strange constant followed by a shift of edx, work out 2^(32+shift) / constant to find the divisor.
