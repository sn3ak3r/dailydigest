# Reverse-a-function drill — 2026-10-31

Target: Windows x86-64 (args in `ecx`, `edx`).

Reverse this short function to equivalent C:

```asm
mystery:
    mov     eax, ecx
    mov     ecx, edx
    shr     eax, cl
    and     eax, 1
    ret
```

Why does the function copy `edx` into `ecx` before shifting?

---

## Answer

```c
unsigned mystery(unsigned x, unsigned n) {
    return (x >> n) & 1;   // value of bit n of x
}
```

## Explanation

- On x86 a variable shift count must live in `cl`; `shr eax, edx` doesn't exist, so the 2nd arg (`edx`) is moved into `ecx` after `x` has been saved to `eax`.
- `shr` is logical (zero-fill), so bit `n` lands in bit 0; `and eax,1` masks off everything above it.
- The count is masked to 5 bits by the CPU for 32-bit operands, so `n >= 32` behaves like `n & 31`.
