# Decode-one-instruction drill — 2026-10-27

Target: Windows x86-64.

Decode this instruction, found between two functions at `0x140001040`:

```
0F 1F 44 00 00
```

What is the assembly, and what does it do? Why would a compiler emit something this odd?

---

## Answer

`nop dword ptr [rax+rax*1+0x0]` (a 5-byte NOP; changes no registers or flags).

- `0F 1F /0` is the multi-byte NOP: it has a ModRM byte, so it can be sized to any length. Here ModRM `44` = mod 01, reg 000 (/0), rm 100 (SIB follows); SIB `00` = base rax, index rax, scale 1; the disp8 is `00`. The memory operand is never accessed.
- The assembler or linker uses it as padding to align the next function (here to `0x140001050`, a 16-byte boundary). One 5-byte NOP executes faster than five single-byte `90`s.
- Other sizes: 2 bytes = `66 90`, 3 = `0F 1F 00`, 4 = `0F 1F 40 00`. Disassemblers often show runs of these between functions.
