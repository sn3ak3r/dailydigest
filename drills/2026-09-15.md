# Decode One Instruction — 2026-09-15

Target: Windows x86-64.

At address `0x00007FF6A1B2C050`, the disassembler shows these raw bytes:

```
74 F6
```

Decode this instruction fully: give its mnemonic and operand, explain how
the operand is encoded, and compute the exact target address it jumps to.

---

## Answer

**`JE 0x00007FF6A1B2C048`** (jump if equal / ZF=1) — a short conditional
jump with a signed 8-bit relative displacement.

- `0x74` is the one-byte opcode for `JE`/`JZ` (short form, rel8 encoding).
- `0xF6` is the displacement byte, interpreted as signed: `0xF6` = -10.
- The target is computed from the address of the *next* instruction, not
  the jump itself: next_rip = `0x00007FF6A1B2C050 + 2` (instruction is 2
  bytes long) = `0x00007FF6A1B2C052`. Target = next_rip + (-10) =
  `0x00007FF6A1B2C048`.

Since the displacement is negative, this jumps backward — a classic
bottom-of-loop branch (e.g. `cmp`/`je` looping back to the top while a
counter hasn't hit its terminal value). Short `Jcc` opcodes (`0x70`-`0x7F`)
only reach ±127 bytes; anything farther requires the two-byte `0x0F 8x`
near-jump form with a 32-bit displacement instead.
