# Decode: 2026-09-03

**Challenge.** Windows x64, no additional prefixes. Given the raw byte sequence:

`41 55`

Decode this into a single x86-64 instruction. State:
1. What each byte contributes (prefix vs. opcode).
2. The full instruction (mnemonic + operand).
3. Why a REX.W prefix is unnecessary here even though the operand is 64 bits wide.

---

**Answer:** `push r13`

**Explanation:**
- `41` is a REX prefix with only the B bit set (REX.B, `0100_0001b`). REX.B extends the 3-bit register field that's encoded *inside* the following opcode byte, letting `push`/`pop` reach r8-r15 in addition to the legacy rax-rdi encodings.
- `55` is the opcode `0x50 + reg`, where the embedded `reg` field is `101b` (5), selecting rbp *or* r13 depending on REX.B. With REX.B set, the field extends to `1101b` = 13, so the register is r13.
- No REX.W appears, and none is needed: in 64-bit mode PUSH/POP always default to a 64-bit operand — there's no 32-bit push encoding to override. (A `0x66` prefix can force a 16-bit push, but REX.W has nothing to do here.) That's different from arithmetic/mov opcodes, where REX.W is what selects the 64-bit form.
