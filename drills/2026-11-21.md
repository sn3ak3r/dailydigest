# Decode-one-instruction drill — 2026-11-21

Target: Windows x86-64.

A function receives a signed 32-bit `int` in `ecx`. You see:

```
D1 F9
```

There's no immediate byte. Decode it. Then: if `ecx` holds -7, what does it hold afterwards? Is that the same as C's `-7 / 2`?

---

## Answer

`sar ecx, 1`: arithmetic shift right by one. -7 becomes **-4**, but C's `-7 / 2` is **-3**.

- `D1` is the shift group's "by 1" form, so the count 1 is built into the opcode and needs no imm8 (compare `C1 /4 ib`, the SHL form you decoded earlier). ModRM `F9` = `11 111 001`: mod=11 means register-direct, reg=111 is the opcode extension **/7 = SAR**, rm=001 = ecx.
- SAR copies the sign bit into the top bit, so negative numbers stay negative. That makes it divide by 2 *rounding toward −∞*. `/5 = SHR` (`D1 E9`) fills with 0 instead, so it's an unsigned divide.
- C rounds toward zero, so for signed `x / 2` compilers first add 1 to negative values (often with `shr eax,31` / `add`) and then `sar`. A bare `sar` usually means `>> 1` in the source, or that the compiler proved the value is never negative.
