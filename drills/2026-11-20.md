# Crackme: find the password (Windows x64, arg in rcx)

`rcx` holds a pointer to a null-terminated ASCII string.

```
check:
    movzx  eax, word ptr [rcx]   ; load 2 bytes at once
    xor    eax, 0x2020
    cmp    eax, 0x6B6F
    jne    fail
    cmp    byte ptr [rcx+2], 0
    jne    fail
    mov    eax, 1
    ret
fail:
    xor    eax, eax
    ret
```

`word ptr [rcx]` reads the first two characters as one 16-bit number. x86 is little-endian: the byte at the lower address (the first character) becomes the *low* byte of the number. Which string makes `check` return 1?

---

**Answer:** `"OK"`

1. Undo the xor (it's self-inverse): 0x6B6F ^ 0x2020 = 0x4B4F, so the loaded word must be 0x4B4F.
2. Little-endian: low byte 0x4F ('O') is the first character, high byte 0x4B ('K') is the second — reading the hex left to right gives "KO", which is backwards.
3. The `[rcx+2] == 0` check forces exactly two characters. (Bonus: xor 0x20 flips ASCII case, so the constant 0x6B6F is just "ok" in lowercase.)
