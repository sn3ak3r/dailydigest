# Reverse-a-function drill — 2026-11-16

Target: Windows x86-64 (arg in `ecx`, return in `eax`).

Reverse this short function to equivalent C:

```asm
mystery:
    lea     eax, [rcx+15]
    and     eax, -16
    ret
```

What does it return for 0, 1, 16, 17 and 40?

---

## Answer

```c
unsigned mystery(unsigned x) {
    return (x + 15) & ~15u;   // round x up to a multiple of 16
}
```

Results: 0, 16, 16, 32, 48.

## Explanation

- `lea eax, [rcx+15]` just computes x+15 into eax; nothing is read from memory.
- `-16` is 0xFFFFFFF0 in two's complement, the same as `~15`: all bits set except the low 4. ANDing with it clears those 4 bits, rounding down to a multiple of 16.
- Adding 15 first turns "round down" into "round up": exact multiples stay put, anything else moves to the next one. Allocators and stack setup use this align-up idiom constantly.
